# V5 execution interfaces

Run commands from the repository root with `PYTHONPATH=src`. Use an existing
environment containing the project dependencies. GPU commands require an
allocated device; the scripts do not choose a scheduler or GPU themselves.

## Data

`scripts/mavt4d/build_v5_manifest.py --help` describes archive ingestion.
It writes a new manifest and audit instead of extracting the corpus. Complete
archives are fingerprinted before use. Existing manifests are immutable.

Supported source keys: `openimages`, `openvid`, `nuscenes`, `dl3dv`,
`arkitscenes`, `co3d`, `omniworld_epic`. A configured source must have data in
the requested split. Missing sources are errors, never silently reweighted.
Set both run-level `mixture` and optional `data.mixture` identically.

DL3DV cameras use a reconstructed scene gauge, not guaranteed meters. Unknown
timestamps support reconstruction but not physical-time prediction. ARKit depth
is measured; CO3D depth is reconstructed. EPIC currently provides RGB and timing,
not geometry labels from unvalidated annotation formats. Camera validity and
depth validity are independent. Missing labels never become zero-valued targets.

TAR.GZ random reads stream the archive and can be expensive. Measure data wait
time before a production allocation; storage expansion is an explicit operation.
`data.verify_archive_sha256=true` rechecks hashes at startup; the default checks
frozen size/mtime and retains the builder's SHA256 provenance.

## Correctness smoke

```bash
PYTHONPATH=src python scripts/mavt4d/smoke_v5.py --output outputs/v5-smoke --wandb
PYTHONPATH=src python scripts/mavt4d/smoke_v5.py --output outputs/v5-smoke \
  --restore outputs/v5-smoke/state-restore.pt
```

The default smoke uses the default architecture and image size. `--tiny
--device cpu` is a fast contract check, not a capacity measurement. Smoke data
is synthetic and its scores are not evidence of natural-data performance.
W&B credentials must already be provided to the allocated process; scripts do
not discover credentials or modify login files.

## Training and validation

```bash
PYTHONPATH=src python scripts/mavt4d/run_v5.py --config run.json --output outputs/v5
PYTHONPATH=src python scripts/mavt4d/run_v5.py --config run.json --output outputs/v5 \
  --resume outputs/v5/last.pt
PYTHONPATH=src python scripts/mavt4d/evaluate_v5.py --config run.json \
  --checkpoint outputs/v5/last.pt --suite outputs/val-suite-v1.json \
  --output outputs/val-result-v1.json
```

The full runner requires schema `natural-v5-run-v1`, exactly 20,000 optimizer
updates and effective batch at least 256. Physical microbatches are measured by
real forward/backward/Adam execution; OOM retries preserve the logical batch.
Run locks pin code, model, source weights and inventory. Changes require an
explicit new run, not an incompatible resume. W&B online is required by the
full runner. Use a private run config for local paths and account settings.

Periodic `dev/*` logs are internal diagnostics. The separate frozen validation
suite pins official/group-held-out validation groups, reports actual horizon
seconds, and uses paired masks for copy-last comparisons. Scores are sampled-ray
metrics, not full-frame SSIM/LPIPS. The dense-feature predictor baseline is
explicitly unevaluated until an independently trained checkpoint is supplied;
these checks alone cannot establish predictive superiority.

Trusted material correspondences/instance assignments are optional supervision
contracts. Current raw adapters do not invent them. Consequently content reuse,
canonical consistency and inferred/unknown evidence coverage may be absent on
a source; monitor label coverage before making a disentanglement claim.
